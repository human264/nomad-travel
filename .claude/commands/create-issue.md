# 역할

너는 GitHub 이슈를 체계적으로 작성하는 전문가야.
아래 내용을 기반으로 GitHub 이슈를 생성해줘.

**생성할 이슈:**
$ARGUMENTS

---

# 분석 단계

이슈를 생성하기 전에 먼저 다음을 파악해:

1. **현재 코드베이스 탐색** — 이슈와 관련된 파일, 컴포넌트, 기존 구현을 확인해
2. **이슈 성격 분류** — 아래 중 하나로 분류해
   - `bug` — 잘못 동작하는 기존 기능
   - `enhancement` — 기존 기능 개선
   - `feature` — 새로운 기능 추가
   - `chore` — 리팩터링, 의존성 업데이트 등 기능 외 작업
3. **영향 범위 파악** — 어떤 파일/컴포넌트가 영향을 받는지 확인해

---

# 이슈 작성 규칙

- **제목**: `[타입] 간결한 한 줄 요약` 형식 (예: `[feature] 도시 상세 페이지 구현`)
- **본문**: 아래 출력 형식을 정확히 따라
- **Label**: 분류에 맞는 label 1개 (`bug` / `enhancement` / `feature` / `chore`)
- 구현 방법은 적지 마. "무엇을"과 "왜"만 기술해. "어떻게"는 PR에서 다룬다

---

# 실행

분석이 끝나면 아래 명령어로 이슈를 생성해:

```bash
gh issue create \
  --title "[타입] 제목" \
  --label "label명" \
  --body "$(cat <<'EOF'
## 요약

[이슈를 2-3문장으로 요약. 무엇이 문제이거나 왜 필요한지]

## 배경

[현재 상태와 이 이슈가 필요한 이유. 관련 파일/컴포넌트 경로 포함]

## 목표

- [ ] [달성해야 하는 것 1]
- [ ] [달성해야 하는 것 2]
- [ ] [달성해야 하는 것 3]

## 완료 기준

- [ ] [눈으로 확인 가능한 기준 1]
- [ ] [눈으로 확인 가능한 기준 2]
- [ ] `npm run build` 성공
- [ ] `npx tsc --noEmit` 에러 없음

## 관련 파일

- `경로/파일.ts` — 관련 이유
- `경로/파일.tsx` — 관련 이유

EOF
)"
```

이슈가 생성되면 생성된 이슈 URL을 출력해줘.
