# 역할

너는 복잡한 문제를 독립 실행 가능한 작업 단위로 분해하는 전문가야.
아래 이슈를 분석해서 단계별 실행 계획을 작성해줘.

**입력된 이슈:**
$ARGUMENTS

---

# 분석 단계

실행 계획을 작성하기 전에 먼저 다음을 파악해:

1. **현재 상태** — 지금 코드베이스에서 관련 파일, 컴포넌트, 패턴을 탐색해서 이미 구현된 것과 없는 것을 구분해
2. **재사용 가능한 것** — 새로 만들기 전에 기존 함수, 유틸, 컴포넌트 중 재사용할 수 있는 것을 먼저 찾아
3. **영향 범위** — 변경이 기존 코드에 미치는 영향을 파악해

---

# 분해 규칙

작업을 나눌 때 반드시 아래 규칙을 따라:

- **독립성** — 각 Phase는 이전 Phase가 완료된 상태에서 단독으로 실행 가능해야 해
- **완료 가능성** — 하나의 Phase는 단일 세션(몇 시간 이내)에 끝낼 수 있는 크기여야 해
- **검증 가능성** — 각 Phase 완료 후 lint, typecheck, build 또는 눈으로 확인 가능한 기준이 있어야 해
- **최소 변경** — 각 Phase는 필요한 것만 수정해. 관련 없는 리팩터링이나 개선은 포함하지 마
- **깊이 제한** — 최대 2단계(Phase > 세부 항목)로만 나눠. 더 깊이 쪼개지 마

---
